# UU Remote 4.41.2.2602 static review

This note records privacy-safe static evidence for UU Remote `4.41.2.2602`.
It is not a controller-input or live-promotion acceptance record. Proprietary
binaries, raw logs, account state, device identifiers, tokens, screenshots,
and host-specific paths remain outside the repository.

## Input-backend redesign

The 4.39.x compatibility manifests forced three virtual-input decisions to
`false` so Wine stayed on the built-in SendInput path instead of an unavailable
kernel-driver path. Those exact assumptions no longer hold in 4.41.2.

Static inspection of 4.41.2 found:

- `USER32.dll!SendInput` remains imported.
- `input_backend_initialized backend=send_input` is present and referenced by
  the backend constructor/initialization path.
- A transition from `send_input` to `vhid` is explicitly logged only after
  a `probe_available` condition.
- A failed vhid open reports
  `current=send_input requested=vhid reason=vhid_open_failed`.
- Runtime failure paths explicitly transition from `vhid` back to
  `send_input`, including `release_all_failed`.
- The old 4.39.x constructor patch signature has no exact or masked candidate
  in 4.41.2.
- The older `gvinput_open ... fallback=send_input` and
  `gvinput_send ... fallback=send_input` landmarks are gone, consistent with
  the backend-state-machine rewrite.

The persisted-setting and runtime-setter byte patterns still have close
relatives in the new binary, but preserving the old forced-false patches would
override upstream's new backend-selection state machine rather than merely
restore the old fallback behavior.

## Native-compatible manifest decision

The reviewed 4.41.2 manifest therefore uses:

```json
{
  "server": {
    "patch_mode": "native",
    "patches": []
  }
}
```

For this mode the audited original and runtime server SHA-256 values are
identical. The patch tool verifies the exact binary and reports that no binary
patch is required; it does not create a server backup or rewrite the file.

This static decision means only that the old binary patch is not justified for
this exact server build. It does not prove end-to-end controller behavior.

## Driver-helper continuity

The bundled `devcon.exe` is byte-identical to the already audited helper from
the 4.33-4.39 releases. The bridge continues to suppress it and retain an
audited backup rather than allowing Windows driver installation inside Wine.

## Runtime acceptance still required

Before adding a top-level `acceptance` object or permitting unattended
promotion, validate this exact release on a disposable prefix and then with a
real controller session:

1. the server cold-starts and remains alive for at least 270 seconds;
2. UU reports the Ubuntu device online;
3. mouse motion, buttons, wheel, drag, and keyboard events work;
4. text/IME, shortcuts, and clipboard behavior remain correct;
5. disconnect/reconnect and service restart recover cleanly;
6. the bridge verifier passes for the native-compatible server state; and
7. uninstall dry-run and rollback checks pass.

Until those checks are recorded, automatic promotion remains fail-closed.
